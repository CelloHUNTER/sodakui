## ポイント・経験値の表示とセキュリティ
- 決定：ポイント・経験値は、子ども本人の画面に表示し続ける（必須）
  - 理由：経験値はキャラの進化、ポイントは餌・お部屋カスタマイズの通貨。数値が見えることが、やる気と算数の学習につながる（ユーザー、2026-11-21）
- 決定：データベースの保護は「表示を消す」ではなく「関係ない人が直接読み書きできない」形で行う。方式は提案中（子どもが先生の students を直接読まない形にする案）。決まり次第ここに追記
- 決定：A案＋C案で進める（2026-11-21、ユーザー承認）
  - A案：先生の端末が、部屋の参加者の経験値・ポイントを部屋側へコピーし、子どもはそこから表示する。子どもから teachers/{uid}/students への読み書きは無くす（キャラ選択は部屋の参加者データに書き、先生の端末が students へ反映）
  - C案：最初に参加した端末の匿名uidを、そのニックネームの持ち主として記録する。先生の画面から、名前の紐づけをリセットできるようにする
    - 理由：iPad は子ども1人1台の専用で、1年間使い続ける。端末の交換などに備えてリセットを用意する
  - 授業後に消してよいのは、部屋にコピーした経験値・ポイントだけ。回答データと記録（CSVのもと）は絶対に消さない。消す対象とタイミングは、実装前に一覧で確認する
  - まだ児童は使っておらず、Firestore のデータはすべてユーザーのテストデータ。データ構造の変更で古いデータの移行は不要（消して作り直してよい）
- 決定（2026-11-21、ユーザー回答）：授業後に消すのは部屋にコピーした経験値・ポイントだけ。タイミングは「先生が部屋を閉じたとき」と「先生の画面を開いたとき、24時間より前の部屋のコピー」。がんばりカードの表示中は消さない。紐づけ情報（名前→端末uid）は students/{名前} に置く（授業後も消さない）
- 決定：ポイントは授業以外の時間にも使う通貨なので、子どもが部屋の外でも自分の数値を見られる必要がある
  - 理由：第2段階で、餌をあげる・お部屋をカスタマイズするのに使う。想定は学校の休み時間など（家庭での使用は想定していない）
  - 方針：C案の紐づけ（名前→端末uid）を使い、「本人の端末だけが自分の students を読める」ルールを今回のルール見直しで検討する。ポイントを使う（書き込む）仕組みは第2段階で決める
  - メモ：第2段階で子どもが授業以外の時間にポイントを使う場合、A案（部屋の中だけで数値が見える）では足りない可能性がある。第2段階の設計時に再検討する
  - 決定（2026-11-21、ユーザー承認）：A案の部屋コピーと、授業後・24時間後の削除処理は **やめる**。本人読み取り（students/{名前}.ownerUid と一致する端末だけが読める）に一本化する。そのため「消す」処理は無く、回答・記録は消えない
  - 決定：Firebase CLI は、デプロイ・ログインには使わない。エミュレータでのルールテスト実行は可（デモ用プロジェクトID。CLAUDE.md を更新済み）
  - 決定：子どもの iPad は、先生がホーム画面に追加する（Safari の保存データが消える可能性への対策）。ただし QR を読むと Safari で開き、ホーム画面アプリとは保存領域が別になるはず（ユーザー指摘、iPad実機で要確認）。端末のuidが違うと紐づけ済みの名前に入れないため、子どもはホーム画面アプリを開いて部屋コードで参加する流れを考慮する（play.js の変更で対応）
  - 実装：firestore.rules と tests/ を作り直した（エミュレータ100項目に合格。まだ Firebase には未反映）
- 決定（2026-11-23、ユーザー承認）：子どもの画面の数値表示（play.js）
  - 経験値は、ポケモンのような横向きの経験値バーで見せる（ユーザー提案。嬉しさが倍増するため）。ポイントは数字で見せる。ラベル・記号（★ けいけんち、◆ ポイント）・数字を併用し、色だけに頼らない
  - 表示場所：待ち画面、答え合わせ（獲得分だけバーとポイントが増える）、がんばりカード（「ぜんぶで」）、部屋コード入力の画面（授業の外。自分のキャラと数値。読み取りのみ）
  - 【仮値】バーは100経験値ごとに満タンになり、「Lv.」を表示する。進化のしきい値は未決定のため、仮に置いた（EXP_PER_LEVEL＝100。play.js）。進化のしきい値を決めるときに差し替える
  - 名前を選んだら「○○さんで いい？」の確認を出し、初回だけ紐づける（間違えて他の子の名前で紐づけるのを防ぐ）
  - iPad の Safari のタブで開いたときは、ホーム画面アプリから開くよう案内を出す（案2：案内は出すが、そのまま紐づけもできる）。理由：先生同士のお試しをスマホ同士でする場合があるため。スマホ（iPad 以外）では案内を出さない
  - ホーム画面アプリ用に manifest.webmanifest と icon（ねこの絵）を追加した。起動先は play.html
- 決定：ルールでも、部屋の roster に含まれるニックネームだけが参加（players・answers の作成）できるようにする
  - 理由：アプリ側だけの制限だと、部屋コードを知っている人が任意の名前で参加できてしまうため（2026-11-21、ユーザー承認）

## ふくしゅう
- 決定：間違えた問題の解き直しは、復習して覚え、再学習で知識を定着させるのが狙い（Kahoot にはない機能。PHILOSOPHY.md の 6）
- 決定（2026-11-23、ユーザー選択：案B）：解き直しの加点は、「問題ごとに、解き直しで初めて正解したとき」だけ1問2点
  - 理由：1回目に間違えた問題を直せたことが評価されるようにするため（PHILOSOPHY.md の 6：復習して覚え、再学習で知識を定着させる）。同じ問題では1回しかもらえないので、繰り返して稼ぐことはできない
  - 以前の「最初の完了1回だけ」は、1回目に間違えた問題を2回目に直しても点にならなかったため見直した（以前の理由は未記録）
  - 2回目以降は、まだ直せていない問題だけを出す（ユーザー承認）。全部直せたら、ボタンを出さず「ぜんぶ なおせた」と表示する
  - 記録（records）は、完了ごとに1行ずつ残す（ユーザー承認）。1回目の点数が上書きで消えない。何回目かは attempt に入れる
  - 正解かどうかは、先生の端末が回答と正解から数え直す（子どもが書いた正解数は信用しない）。加点済みの問題は paid に記録する（先生の端末だけが書ける）
  - 限界：採点は先生の画面を開いている間だけ付く。先生の画面が閉じている間に続けて2回挑戦すると、1回目の回答は上書きされ、2回目の分だけで加点される
- 決定：先生の画面から、選んだ子の端末の紐づけを解除できる（ownerUid と claimedIn を消す）。経験値・ポイント・キャラ・記録は消えない。iPadの交換や保存データの消去のときに使う（2026-11-23、ユーザー依頼）
- 決定：「先生が部屋を用意する方式」をやめ、結果発表後のがんばりカードのボタンから入る方式に変更（2026-11-19）。対象は間違えた問題と答えなかった問題だけ
  - 理由：未記録（要確認）
- 決定：ゲーム終了時に先生の端末が答え（keys）を部屋へ公開する（ゲーム中は渡さない）
  - 理由：子どもの端末で答え合わせしながら解き直すため。ゲーム中の不正を防ぐため、終了後だけ公開
- 決定：rooms.keys は「問題番号→正解の配列」のオブジェクト形式
  - 理由：Firestore は配列の配列を保存できない（PR #36 の不具合の原因）
