# そだクイ の想い（PHILOSOPHY.md）

このファイルは、機能を考えるときの「ものさし」。毎回読む。
「なぜそうしたか」を書く。理由が分からないものは推測で書かず、【要確認】と書いて人間に聞く。

最終更新：2026-11-21（初版。【要確認】は未回答）

## このアプリは誰のため？
- 特別支援学校・小学部の学級で、先生と児童がいっしょに使う
- 4択クイズに答えると、キャラクターが育つ
- 本番の端末は、先生・児童ともに iPad（Safari）

## 大切にしていること

### 1. 数値が見えること（やる気と算数の学習につながる）
- ポイント・経験値は、子ども本人の画面に表示し続ける。これは必須
- 理由（ユーザーの言葉）：経験値はキャラの進化、ポイントは餌やお部屋のカスタマイズに使う「通貨」。数値が見えることが、やる気と算数の学習につながる
- だから、数値を隠す方向のセキュリティ対策は取らない。「表示は残したまま、関係ない人がデータベースから直接読み書きできない」形で守る

### 2. 子どもの個人情報を守る（最優先）
- 児童の本名・写真を扱う機能は作らない。記録はニックネームに紐づく学習ログ（回答・正解数など）だけ
- 児童はログインなし。QR で参加し、ニックネームとキャラ選択だけ
- テストデータにも、実在しそうな氏名は使わない
- 理由：【要確認】（学校・自治体のセキュリティポリシーの確認が本番前に必要、とは PRODUCTION.md にある）

### 3. 費用ゼロ・AIに頼らない
- Firebase は無料の Spark プランだけ。有料プラン（Blaze）には移らない
- アプリ自体は AI で動かさない（AI は制作時だけ）
- 理由：【要確認】

### 4. 色だけに頼らない
- 選択肢は、色だけでなく記号（◯△など）を併用する
- 理由：【要確認】

### 5. 先生が主役、先生の手元で完結
- 先生はログイン制・招待制。クイズの共有は「コピーを渡す」方式
- 採点と記録は先生の端末が行う。キャラの変更も先生側のリセットだけ（子ども側に変更ボタンは付けない）
- 理由：【要確認】（技術的な理由は Cloud Functions を使わないこと、とは分かっている）

### 6. 順位・間違いとの付き合い方
- 結果発表は3位→2位→1位。4位以下は順位を出さず、同じ大きさのタイルで結果だけを見せる
- 間違えた問題は、がんばりカードのボタンから、間違えた問題・答えなかった問題だけを解き直せる（ポイントももらえる）
- 理由：【要確認】

### 7. キャラクター
- 全19系統。子どもたちに一覧を見せて選んだ（2026-11-19）。子どもたちのリクエストで追加した系統がある（鶴の恩返し・牛若丸・フグ・バス）
- パートナーは1匹選ぶ。変更は先生だけ
- 理由（なぜ育成なのか、なぜ変更できないのか）：【要確認】

### 8. 授業の邪魔をしない
- 授業の直前に大きな変更を入れない

## やらないこと
- 児童の実名・写真・イニシャルを扱う
- Cloud Storage / Cloud Functions / Realtime Database の利用、有料プランへの移行
- 秘密情報（サービスアカウント鍵、パスワード等）のコミット
- 想いとぶつかる依頼は、実装の前に指摘する。変えるかどうかは人間が決め、変えるときはこのファイルも更新する
